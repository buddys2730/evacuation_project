# 04. 開発・運用ルール・ガイドライン

## 1. Gitフロー

- ブランチ戦略  
  - `main`：常にリリース可能な安定版  
  - `develop`：日常的な開発作業用  
  - `feature/xxx`：新機能ごとに作成  
  - `hotfix/xxx`：緊急修正用

- プルリクエスト（PR）ルール  
  - 必ずレビューを通す  
  - 自動テストがすべてパスすること  
  - コミットメッセージは規約に準拠

- コミットメッセージ規約  
  - 例: `feat: 新機能追加`、`fix: バグ修正`、`docs: ドキュメント修正`

---

## 2. コーディング規約

- 言語別スタイルガイドに準拠  
  - Python: PEP8  
  - JavaScript/React: Airbnb Style Guide  
- 静的解析ツールの活用  
  - ESLint, Prettier, flake8 など

---

## 3. Issue管理・タスク管理

- GitHub Issuesで管理  
- タスクは必ず担当者を割り当てる  
- 進捗は定期的に更新する

---

## 4. コミュニケーションルール

- Slackをメインチャネルとする  
- 重要な決定はドキュメント化し共有  
- 週次ミーティングで進捗報告

---

## 5. その他

- コードレビューは相互に丁寧かつ建設的に行う  
- セキュリティ、プライバシーを常に意識する
