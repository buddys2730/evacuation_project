## 0. セットアップ・前提環境

- 必要環境：
  - Python 3.10+
  - Node.js 18+
  - PostgreSQL + PostGIS
  - Git
- **データベース初期データ（SQL/GeoJSON）は `database/seed_data/` 等ローカルに必ず保持**
- `.gitignore` で大容量データ/機密情報はGit管理外（後述運用ルール参照）
- OSはMac/Linux/Windowsどれでも可（M1/M2 Mac対応済み）

1. 概要

本システムは災害状況（危険区域ポリゴン）の登録・検索・地図表示を行うWebアプリ＋APIです。
管理者はポリゴン（地図上の範囲）、災害種別、深さ、危険度、コメント等を登録でき、登録内容は地図上で一覧・可視化できます。

3. DBテーブル仕様

disaster_situations（危険区域・災害状況）

| カラム名           | 型        | 説明          |
| -------------- | -------- | ----------- |
| id             | int      | PK          |
| disaster\_type | str      | 災害種別（例: 洪水） |
| danger\_level  | str      | 危険度（高/中/低）  |
| depth\_m       | float    | 深さ(m)       |
| is\_closed     | bool     | 通行止めフラグ     |
| geometry       | POLYGON  | ポリゴン(GIS型)  |
| occurred\_at   | datetime | 発生日         |
| cleared\_at    | datetime | 復旧日         |
| comment        | text     | コメント        |
| image\_url     | text     | 画像URL       |
| created\_at    | datetime | 登録日         |
| updated\_at    | datetime | 更新日         |

4. API仕様

[POST] /api/disaster_situations
新規災害状況の登録

Body例

{
  "disaster_type": "洪水",
  "danger_level": "高",
  "depth_m": 2,
  "is_closed": true,
  "geometry": { "type": "Polygon", "coordinates": [[[..., ...], ...]] },
  "occurred_at": "2025-06-25",
  "cleared_at": "2025-06-26",
  "comment": "大雨洪水警報",
  "image_url": ""
}

成功時: { "id": 7 }

[GET] /api/disaster_situations
全登録災害状況をGeoJSONで取得（地図描画用）

戻り値例

[
  {
    "id": 7,
    "disaster_type": "洪水",
    "danger_level": "高",
    "depth_m": 2,
    "is_closed": true,
    "geometry": { "type": "Polygon", "coordinates": [[[133.29,34.54], ...]] },
    "occurred_at": "2025-06-25T00:00:00",
    "cleared_at": null,
    "comment": "TEST",
    "image_url": "",
    "created_at": "...",
    "updated_at": "..."
  },
  ...
]

7. よくあるトラブル／デバッグ方法

"can't adapt type 'WKBElement'" エラー
→ geometry取得時は必ずST_AsGeoJSON()で文字列化
"TypeError: cannot convert dictionary update sequence element #0 to a sequence"
→ dict(row)で失敗。.mappings().all()またはd = {k: v for k, v in row.items()}で変換
CORS 500/403エラー
→ Flask側CORS許可 or トンネル側Origin制御を確認
日付型不正
→ datetime型は.isoformat()で文字列化
8. 運用・データ管理ルール（.gitignore等）

database/seed_data/・mergeFromCity_*.geojson等の大容量データは絶対に削除・移動しないこと
これらは .gitignore でGit管理外。必ずローカル＋バックアップ保持
データの共有・配布はクラウド/外部ストレージ等で行う。GitHubには絶対pushしない
新しいデータ拡張子やディレクトリ追加時は、.gitignoreを都度見直し・追記

10. FAQ・引き継ぎ時の注意

Q. クローン直後にデータが無い場合は？
→ データベース初期データ・GeoJSON等は、必ず別途引き継ぎ元から受け取りdatabase/seed_data/に配置
Q. pushで大容量ファイルエラーが出た場合は？
→ .gitignoreとgit rm --cached <ファイル>で除外。履歴混入時はgit filter-repo等で履歴ごと削除
Q. バックアップはどこに？
→ ローカルPC＋外付けHDDやGoogle Drive等、必ず複数保存
Q. 新規ファイル/拡張子追加時は？
→ .gitignoreを修正し、GitHub管理外とすること
Q. 設計・仕様変更時は？
→ 本ドキュメントに追記・履歴化。設計・運用の全履歴はdocs/に保存
